# Feature reference

Detailed behavior and historical release notes. For current installation, setup and screenshots, start with the [README](../README.md).

Version 0.22 adds **More → Re-transcribe…** for any saved meeting, including meetings with imported tasks. Choose another audio model or run the same one again; this starts fresh audio processing. The existing transcript remains available until the new version finishes. Failed/cancelled attempts keep their own resumable checkpoints. **More → Transcript versions…** restores older results, speaker aliases and reviewed task status. Imported Inbox tasks and original audio remain intact.

Version 0.21.1 defaults meeting capture to **System audio + microphone** using a private Core Audio tap on macOS 14.2+. It records all applications’ output without an application picker or video. Selected-app and microphone-only modes remain available. Continuous resampling and mix headroom reduce packet-boundary crackle and clipping. Original tracks are preserved; existing playback/upload mixes rebuild with the improved mixer. **whisper-1** automatically uses timed `verbose_json` without unsupported diarization fields. Its transcript has no individual speaker labels.

Version 0.20 adds reusable meeting speaker aliases and an explicit **Me** identity. Open **Speakers…** above the player, assign the same alias to matching labels, and rename aliases by clicking their chips. Your speaking segments stay pink, and task suggestions appear as **Mine → Unassigned → Others**.

Version 0.19.1 processes long meetings in uploads of at most three minutes, preferring nearby quiet boundaries. Timeouts split a chunk further; transient failures retry with bounded backoff. Completed audio chunks and analysis batches are saved, so **Resume processing…** continues unfinished work after failure or restart. Playback files and original recordings stay intact. Offline validation covers a full hour of audio and restart recovery. Analysis uses short evidence references, restores durable timecodes/speaker identities locally, and retries malformed replies up to three times without discarding completed batches.

Meeting analysis errors identify the failing stage, model and endpoint. If transcription succeeded and summary/task extraction failed, use **Extract tasks from transcript…** to retry the saved text. The text-model alias is configured separately under **Settings → Task cleanup**.

Version 0.18.2 fixes combined meeting recording failing with “Could not read microphone audio.” Microphone-only and combined recording now share the AVAudioEngine input path; native call-audio packets are copied into owned PCM buffers, and empty startup packets are ignored. A real combined capture on the target Mac saved both tracks successfully.

Version 0.18 simplifies the main screens and adds a persistent status bar. Warnings and full sync messages open from its warning count; supporting explanations stay in collapsed Details sections. Today combines the day’s work and current meetings in one timeline. Schedule transitions, unscheduled tasks and calendar display options remain available on demand.

The menu bar uses the colored gold ring. Its panel and app menu offer **Record meeting…** while idle and **Stop & save recording** during capture. The Eye appears in the menu bar only while a meeting is recording (and briefly while saving); click it for the timer and stop control. It stays hidden during setup, transcription and playback. **Settings → Event alerts** controls native alerts and sounds one minute before selected Google Calendar events, scheduled tasks and routine occurrences. Alerts follow Google moves and deletions, avoid mirrored duplicates, and skip completed work, all-day events and unconfirmed drafts. The app requests macOS notification permission once; denied access can be changed in Notification settings. Keep the app running in the menu bar for ongoing calendar changes. The next 48 hours (up to 60 nearest alerts) are scheduled with macOS, including while the planner window is closed; Focus and system notification preferences apply.

A native personal macOS planner with a photoreal polished gold ring, menu bar access, quick capture, explicit task triage, and a local daily planning engine. Swift, SwiftUI and AppKit. Requires macOS 14 or newer; developed on Apple silicon, macOS 26.5.

## Run

```sh
./scripts/build-app.sh --install
```

Builds an application signed with a persistent local identity, installs it into `~/Applications`, and opens it. The ring remains in the macOS menu bar after the main window closes. Press **Control + Option + Space** anywhere to capture; **Command + Return** opens task review. Press **Control + Option + R** to start or stop recording into Inbox; its microphone button does the same. Stopping speech opens cleanup and review. Confirm selected drafts to save tasks. Quit from the menu bar popover or Command + Q.

For a disposable example workspace (sample tasks and a clearly marked example meeting):

```sh
open -n "build/The One Ring Planner.app" --args --demo
```

For a larger matrix preview, add `--matrix-demo` alongside `--demo` to seed twelve extra example tasks per quadrant. Add `--demo-live-clock` to exercise periodic clock updates while keeping the example workspace isolated. Use `--demo --calendar-sync-demo` to preview tasks and routines moved to tomorrow, with Q2 scheduled, draft, pending and unscheduled states.

A normal launch starts with an empty inbox. Routine templates are disabled until their preferences are confirmed. `--menu-bar-only` suppresses the main window at launch. Login-item registration is not included yet.

## What works

- Native Today timeline, persistent right-hand Inbox sidebar, four-quadrant matrix, routine preferences, daily review, and planning settings in system light and dark appearances.
- **Routines → New routine** creates named routines with duration, a time window, importance/urgency, protected or flexible placement, and an icon/celebration. Repeat every day, weekdays, weekends, or selected weekdays. Edit any routine or pause it with **Include in future drafts**. Replan applies repeat-day changes to unstarted occurrences, including pins; completed and running occurrences remain. Repeat days use your planning time zone, and each day's completion is independent.
- Menu bar popover and Carbon global shortcuts for text capture and Inbox voice capture, without Accessibility permission.
- LiteLLM cleanup of typed and dictated captures into concise action titles, supporting notes, suggested project/product tags, and multiple task proposals when appropriate. Every proposal is editable and selectable; nothing is saved until confirmation. The original capture is preserved separately and linked to confirmed tasks in one transaction. T1A and 8FDE spellings are normalized. Existing Inbox items have **Refine with AI…** in their more menu; refinement preserves task identity and explicit planning choices, and checks for stale revisions.
- Project/product tags displayed in Inbox, matrix and timeline rows, editable in task and priority review. Inbox and matrix can filter by any tag and group by the first tag without duplicating tasks. Untagged work stays visible. Existing task records migrate without losing state, effort, notes or dependencies.
- Explicit importance, urgency and effort choices; effort presets; resume notes; waiting and archived states. AI capture creates unclassified Inbox tasks and does not infer planning decisions.
- Task details include **Task actions → Move to Inbox, Archive task, Delete task…**. Inbox and archival remove future task blocks and pause running work. The matrix's **Archived** list lets you inspect or restore archived tasks. Deletion removes the task and its saved plan entries; original captures and Git history remain, and dependent tasks stay blocked until their prerequisites are reviewed.
- Priority dropdowns on matrix and Inbox tasks, plus drag-and-drop from Inbox into any quadrant and between quadrants. Grab a task's title or grip; each quadrant stays visible and scrolls its own tasks. Missing titles, duration estimates or useful block lengths must be confirmed before a task moves; cancelling leaves it unchanged. Reprioritization preserves task identity and execution state and saves to Git without silently rebuilding a plan.
- The priority matrix uses compact rows with effort, project tags and a priority menu on one metadata line, task counts, and independent scrolling in all four quadrants. Search titles, contexts or tags. Each quadrant has an **Expand** control that opens its full task list in native macOS full screen, with unabridged titles, task editing, priority changes and Q2 calendar scheduling. Switch quadrants directly, filter/group by tag, and return using **Back to matrix** or **Escape**; search and tag choices are retained. Navigation and Inbox return when you leave the expanded view.
- Moving a task into **Q2** automatically opens a time-slot review after any missing details are confirmed. It searches the next seven workdays around calendars, existing planned work, routines, transitions and reserve. **Find another time** rejects a proposal without booking it; change the start date, earliest time, block length or weekend setting to refine the search. **Accept & add to calendar** pins and queues only that booking. Already allocated effort is deducted so a task is not booked twice. Existing Q2 tasks also have **Find calendar time**.
- Q2 rows show a scheduled date and time, or an explicit **Draft**, **Pending**, or **Not scheduled** state, in both compact and expanded views. Clicking a date opens that day; its tooltip lists upcoming blocks in the planning time zone. Calendar bookings take precedence over unsent drafts in this summary.
- **Calendar** supports dragging a task or routine to another time or visible day, with a live preview and five-minute snapping. Drag its top or bottom edge to resize (5 minutes–24 hours), or click it and choose **Move or resize…** to enter any date/time. Moving a local draft publishes that occurrence only. Existing Google events retain their IDs, colors and other details; edits patch only start/end. Routine edits affect one occurrence and preserve the repeat template. Task resizing adjusts remaining effort by the duration difference while retaining other chunks and completion history. Completed, running and external meeting events are read-only.
- Calendar edits are saved locally before sending. Pending changes survive restart and retry with backoff; failures stay visible above the grid. If Google changed the same event, **Use Google time** imports its latest times, while **Apply my time** explicitly retries your proposed times against a fresh version. Deleted Google events are not silently recreated. The edit queue is independent of full-day publication, so one move does not confirm unrelated drafts. Q2 dates show pending edits.
- Moving a planner-created task or routine in Google Calendar updates its saved schedule on calendar refresh, app activation, and the five-minute background refresh. Stable event IDs find moves to another date as well as another time. Moved blocks remain pinned, appear on the actual day, and retain completion history. Replanning reserves them without creating or republishing duplicates. Overlaps and work-hour conflicts remain visible. A simultaneous local time edit requires explicit confirmation, and pending publication checks remote times before writing.
- Up to three selected outcomes, deterministic local drafts, work and lunch boundaries, deadline and dependency handling, split focus blocks, shared transition gaps, interruption reserve, pinned and running block preservation, and overflow explanations.
- **Choose tasks** on a day plan, or **Daily review → Prepare tomorrow’s draft**, opens a checklist of eligible tasks. Custom selections are saved for that date and reused by Replan; **Use automatic selection** includes newly eligible work on future replans. Completed and running work stays in the plan. Excluding a task removes its unstarted pinned blocks; meetings and routines follow their own settings.
- The task chooser shows available hours after calendar commitments, lunch, due routines, retained task blocks, transitions and interruption reserve, alongside selected effort and the amount that fits in the draft. Its time breakdown counts overlapping commitments once, excludes elapsed time when planning today, and explains overflow or displaced routines. The selected date is read directly from Google before displaying a connected estimate; read failures offer Retry and prevent building from an unchecked estimate. Disconnected calendars show a clearly labelled local estimate. Previewing and cancelling do not save a plan; Build draft reads the calendar again before saving.
- Start, complete, pause with remaining effort and a resume note; manual routine occurrence completion with guitar, movement and evening-review animations that respect Reduce Motion.
- Optional explicit on-device speech capture (60 seconds maximum); capability and permission checks, an inline Inbox microphone/stop button, editable transcript and typed fallback. On macOS 26+, SpeechAnalyzer transcribes locally without requiring system Siri or Dictation; required language models download with a visible preparation state. Older Macs use the on-device SFSpeechRecognizer fallback with actionable Dictation and permission errors. Stop releases the microphone immediately and waits for final words; closing a window cancels pending setup. Quick capture and Inbox never record simultaneously. Audio is not written to disk. English capture, stopping, and the shortcut have been verified through the default microphone on the target Mac.
- Separate readable JSON Git records and local commits, atomic file replacement, a recoverable write-ahead journal, and restart recovery.
- Direct Google Calendar API integration with browser OAuth, PKCE and a temporary loopback callback, Keychain token storage, automatic token refresh, explicit calendar selection, a Calendar view and Today agenda. Recurrences, all-day events, busy/free and declined events follow Google API responses. Calendars refresh on app activation, every five minutes while running, manually, and before building drafts. Missing authorization/calendars prevents availability-based planning.
- **Confirm & add to calendar** publishes scheduled task blocks and routine occurrences as private busy events in a selected Google calendar you own. **Save draft** stays local. Split task blocks and scheduled routines become separate events at their planned times. Task events use red (Google's Tomato); routine activities use green (Basil). **Settings → Google Calendar → Apply colors to existing events** updates colors on previously created planner events while preserving their times and details. Routine repeat days determine which occurrences enter each confirmed day; no unbounded recurring series is created. Lunch, transitions and unscheduled overflow are not published. Reconfirm an existing day to include its routines. Durable confirmation records retry after restart or connection failure without duplicating events. Reconfirmation updates owned events and removes obsolete blocks; later local changes require confirmation again. Planner-owned events stay visible in Calendar and are excluded from the planner's own availability calculation.

## Current boundary

This is a **local first implementation**, not the PRD release gate. Remote Git synchronization, importing external title/notes changes or deletions, boundary notifications, extension previews, plan revision undo, recurring task creation, monthly/interval routine schedules, and a login item remain for later increments. Google authentication is direct. This personal build requires a Google Cloud Desktop app OAuth client with the Calendar API enabled; Settings includes setup instructions and imports its downloaded JSON. It does not use EventKit or macOS Calendar accounts. Russian accuracy and live recognition on macOS 14–15 are unverified. Routines are placed within the workday and their allowed window. Flexible routines follow task placement, with protected routines reserved first.

Calendar writes require **Settings → Google Calendar → Enable calendar writing** once, then Google consent. A confirmation waiting for permission or a network retry is clearly shown as pending. No successful publication is claimed until all event operations finish. Confirmation checks the selected account and calendar ownership; the app edits or removes only events carrying this workspace's verified identity. External edits racing a write stop it with an error. If a planner event was deleted directly in Google, restore it from Google's Trash before retrying. Calendar selection and a successful last-read timestamp remain visible.

## Google Calendar connection

1. Create or select a Google Cloud project, then [enable the Google Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com).
2. In Google Auth Platform configure the app name **The One Ring Planner** and your support/contact email. Use Internal for an eligible Workspace organization, or External with your own Google account added as a test user. Keep the app private while testing.
3. Under [Google Auth Platform → Clients](https://console.cloud.google.com/auth/clients), create an OAuth client with application type **Desktop app** and download its JSON. See [Google's Desktop OAuth guide](https://developers.google.com/identity/protocols/oauth2/native-app). A web client or API key will not work.
4. In the planner open **Settings → Google Calendar · direct connection → Import OAuth credentials…** and select that JSON. Credentials are stored in Keychain, outside the task repository and preferences.
5. Choose **Sign in with Google**. The system browser handles account selection and consent; the app validates a fresh state and PKCE challenge through a listener bound only to `127.0.0.1` on a random port. No password is collected by the planner. Cancel closes the listener; an unfinished sign-in times out after three minutes.
6. Allow the two read permissions, then select which calendars to include. A successful read (including an empty day) shows a last-read time and connected status. Existing macOS calendar permissions or selections are not reused.
7. To publish tasks and routines, choose **Enable calendar writing**, approve Google's additional event permission, and select an owned calendar in **Publish confirmed plans to**. Your selected primary calendar is the default. Existing confirmed days keep their original destination if this preference changes.

Initial sign-in requests `calendar.calendarlist.readonly` and `calendar.events.readonly`. Enabling publication adds `calendar.events.owned`, which Google defines for creating and changing events on calendars you own; see [Google's scope reference](https://developers.google.com/workspace/calendar/api/auth). Cancelling the upgrade preserves the existing read connection. API calls use authenticated HTTPS with redirects disabled. Access and refresh tokens stay in Keychain; refresh requests are coalesced and a rejected request is retried once with a renewed token. Revoked tokens prompt a new sign-in. Disconnect deletes local tokens and clears the selection; previously confirmed pending publications stay queued and need the same account's authorization before resuming. The Google Account's third-party connections page controls the server-side grant.

External apps in Testing have refresh tokens that expire after seven days for Calendar scopes; the app asks you to sign in again rather than silently hiding meetings. See [Google's token-expiration documentation](https://developers.google.com/identity/protocols/oauth2/). Workspace policy or Google app verification can affect authorization; production distribution needs its own configured OAuth project and verification as applicable.

Agenda and availability list queries use explicitly selected calendars. Previously confirmed planner events are also read by stable ID from their original publication calendar to import time changes. Calendar and event result pages are fully paginated. Google expands recurrences with `singleEvents=true`; occurrences have distinct IDs. All-day dates use the calendar's time zone and exclusive end date, including DST. Cancelled events are excluded; free, declined and working-location events do not reserve time. Invalid event times or failed pages fail the read instead of producing partial availability. Selecting no calendars never reads every calendar. Disconnect/selection changes discard late UI results. Calendar metadata enters local Git history only when included in a saved plan; it is not sent to LiteLLM. Demo mode does not read real calendars.


## LiteLLM connection

In **Settings → Task cleanup · LiteLLM**, enter your gateway base URL, its model alias, and your virtual API key. Save the connection, then use **Test connection** to send a synthetic task through that model. HTTPS is required except for localhost. The app uses the gateway's OpenAI-compatible `/chat/completions` endpoint with validated JSON output. The model must support JSON output.

The key stays in macOS Keychain, outside task files, Git, logs and application preferences. Only the current capture and up to 60 existing tag names are sent; task history, plans and audio are not sent. Gateway retention and provider routing depend on its configuration. Cancel aborts the request. A failed or missing connection preserves the source and offers manual drafts; it never silently saves a raw transcript as a title. Demo mode uses separate connection preferences and a separate Keychain entry.

The adapter and UI workflow have been checked against a local simulated gateway. The meeting workflow was also verified through the saved live gateway as described below.

## Data

The app initializes its own local repository at:

```
~/Library/Application Support/The One Ring Planner/Data/
  tasks/<id>.json
  captures/<id>.json
  completions/<id>.json
  routines/<id>.json
  plans/YYYY-MM-DD.json
  settings/planning.json
```

Recovery journals live in the sibling `Local/` directory and stay outside Git. This data repository is independent of this application source repository. No remote is configured or pushed. JSON uses schema versions, stable IDs, sorted keys and ISO timestamps. Git history retains prior task text after edits, archival or deletion. Original capture text is also retained. Task removal and affected plans are saved in one recoverable transaction. A failed save stays visible and prevents acknowledging capture success.

## Meeting recorder · The Eye (0.12.0)

Open **The Eye** in the sidebar or use its separate Eye icon in the macOS menu bar. Start a recording, choose microphone, call audio, or both, and select the call application in the native macOS sharing picker. ScreenCaptureKit supplies disposable low-resolution frames to its stream; only audio is written to disk. Microphone and call channels are saved independently and aligned by their audio clocks. Headphones help avoid microphone echo. Closing the window keeps recording; the Eye menu can stop and save it. Quitting gracefully closes the recording. A four-hour limit and low-disk-space stop preserve captured audio.

Recordings, transcripts, editable speaker names and task proposals are stored in `~/Library/Application Support/The One Ring Planner/Meetings/<meeting-id>/`, with private folder/file permissions, outside the task Git repository. Interrupted sessions retain their raw audio and completed processing. **More → Show recording files** reveals them; **Move recording to Trash** uses macOS recoverable Trash. Transcript export is a plain-text file. Playback mixes channels into bounded-memory, 20-minute AAC parts and plays them continuously on one absolute timeline. Unchanged mixes are cached locally. Play/pause preserves position; scrub the slider, skip ten seconds, or change speed. Transcript and topic timecodes jump to the corresponding passage.

Choose **Transcribe locally** for an explicit English or Russian recording on macOS 26+. Apple downloads the language assets if needed; language availability depends on successful asset installation on the Mac. Local labels distinguish your microphone and the call channel, not individual remote voices. The October 27, 2026 generated-speech check passed English. Apple's Russian DictationTranscriber advertised support but its asset installation failed on this Mac; the app reports that failure and preserves the audio. Automatic mixed Russian/English and individual speaker separation use the configurable audio model through LiteLLM.

In **The Eye → Audio models**, use **Check available models** to read the saved gateway's authenticated `/models` catalog and optional `/model/info` metadata. Only aliases and capability fields are decoded. Metadata marked `audio_transcription` is preferred; name-based suggestions are explicitly unverified. Set an audio transcription alias separately from the saved text model. Speaker separation requests `diarized_json` with automatic chunking, so it requires a compatible gateway/model. A standard chat alias is insufficient. Speaker IDs restart in each short audio chunk. Open **Speakers…** above the player to assign reusable aliases to those labels, including **Me**. Rename an alias by clicking its chip; assign the same alias to matching labels in later chunks. Aliases are saved per meeting, and people are never identified across meetings automatically. The recording timeline has separate Me/Others lanes: Me is always pink, including overlapping speech. Transcript names, timecodes and the speaker filter follow the same assignments. Task proposals are grouped **Mine → Unassigned → Others**, and owner choices group all labels for one alias together. Changing an alias or owner updates the groups without reprocessing or importing tasks.

**Process audio with LiteLLM…** shows the gateway and both aliases before uploading audio. It sends each AAC part to `/audio/transcriptions`, then the transcript, meeting title, edited speaker names and existing tag names to the saved chat model for summary, decisions and task proposals. **Extract tasks from transcript…** sends text only. Model processing does not create planner tasks automatically. Every proposed task must cite supplied transcript evidence and a valid speaker ID if assigned. Review titles, notes, tags, owner and explicit timing, select the proposals and choose **Add selected to Inbox**. Tasks remain unclassified until normal triage. Only approved task details and short supporting evidence enter task history; the full recording and transcript stay outside Git. A durable import receipt and stable task IDs prevent duplicate imports after interruption. Gateway retention/routing remains governed by the gateway's configuration.

## Complete tasks and review History (0.13.0)

Every compact and expanded priority-matrix row has **Mark completed**. It completes the whole task immediately, even if its planned blocks are on a different day, and does not require the scheduled day to be open. Task details offer the same action, and changing State to Done uses the same transaction. Completing the final work block on the timeline also records a whole-task completion; partial blocks continue to reduce remaining effort normally.

**History** in the sidebar contains Completed and Archived tabs. Completed work is grouped by actual completion date in the planning time zone, with search across titles, details, projects and tags, plus Today/7-day/30-day/all-time filters. Details show a saved snapshot of the task, preserving what was completed even if the active task is later renamed or deleted. **Restore to Inbox** preserves its ID, original creation date, details, tags and source capture, restores its effort estimate for review, and records the restoration time on the completion entry. Returning it to a quadrant requires the usual triage. Repeated completion/restore cycles retain separate entries; only the latest closed completion can be restored. Archived tasks remain available in the separate tab.

Completion, history records and cleanup of every affected saved plan are written through one recoverable Git transaction. Planned chunks, including future pins, are removed; running work closes with elapsed minutes, and prior completed/interrupted work stays intact. A direct whole-task completion does not pretend that future scheduled blocks were worked. Existing Google events follow normal plan reconfirmation: changed plans require confirmation before their obsolete events are removed, and History details link to those future day plans. Completed records live in `Data/completions/` and survive deletion of the active task. Existing Done tasks migrate into History once; older releases did not save completion timestamps, so missing dates are explicitly shown as unavailable rather than inferred from a later edit time.

Six additional core checks cover completion in all four quadrants independent of planned dates, running/future block cleanup and preserved history, repeated restore cycles and snapshot identity, honest legacy migration, persistence and interrupted restoration recovery, and timeline completion metadata/calendar reconfirmation. UI verification uses an isolated `--demo --completion-demo` workspace with a fake published future plan; it never changes real tasks or Google calendars.
